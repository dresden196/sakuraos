Disk layout

The partitions and BTRFS subvolumes the installer creates, and why each one exists.

Partitions

PartitionLabelSizeHolds
EFI system partitionSAKURA_ESP1 GiBThe boot loader and kernel images
SystemSAKURA_ROOTThe restA BTRFS file system labeled SAKURA, optionally inside LUKS encryption

When installing beside another system, SakuraOS reuses that system's existing EFI system partition and creates only the system partition. See Dual boot with Windows.

The EFI system partition is larger than the usual few hundred megabytes because each unified kernel image contains a whole initramfs, and there are two of them: the normal one and recovery. It is mounted at /boot with fmask=0077,dmask=0077, so only root can read it.

Subvolumes

SubvolumeMounted atWhy it is separate
@/The system. This is what restore points capture and what going back replaces.
@home/homeYour files. Never part of a restore point, so going back never changes them.
@log/var/logLogs survive going back, so the record of what went wrong is still there afterwards.
@pkg/var/cache/pacman/pkgDownloaded packages. Large and not worth capturing in restore points.
@snapshots/.snapshotsThe restore points themselves.

Encryption

With encryption, the system partition is a LUKS2 container, opened as cryptroot at start-up, with the BTRFS file system inside it. The EFI system partition is not encrypted, because the firmware has to read it. Both the normal and the recovery kernel image carry the settings needed to unlock it, so recovery works on an encrypted disk too.
