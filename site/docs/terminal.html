Terminal Assist

Terminal Assist stops a small set of commands known to break a system or destroy data, and explains what they would have done. Every stop says how to continue if you meant it.

What the pacman check stops

What the terminal check stops

  • Partial upgrades: pacman -Sy without u, the most common way an Arch-based system breaks. Use pacman -Syu.
  • Removing a package while ignoring what depends on it (-Rdd), and overwriting another package's files (--overwrite '*').
  • Building AUR packages as root, with sudo yay, sudo paru or sudo makepkg.
  • Deleting the system's BTRFS subvolumes, which also deletes the restore points.
  • Commands that erase disks or file systems: rm -rf /, formatting, writing directly to a disk with dd, and discarding a drive's contents.
  • Breaking system permissions or ownership, such as making system files writable by everyone.
  • Running a script straight from the internet, as in curl … | sh. Download it and read it first.
  • A few others: deleting all scheduled jobs, fork bombs, and writing firmware to a drive.

The terminal check looks at the first command on each line you type. A command after ; or && on the same line is not checked, though the pacman check still applies to it.

Continuing anyway

Every stop prints the exact way to continue. For the terminal check, put SAKURA_ASSIST_OVERRIDE=1 in front of the command: 

SAKURA_ASSIST_OVERRIDE=1 sudo pacman -Sy archlinux-keyring

The pacman check wants the name of the rule it stopped, which the message gives you, so that overriding one check does not switch off the others: 

sudo SAKURA_ASSIST_OVERRIDE=glibc pacman -R glibc

Several rules can be named at once, separated by commas.

Changing how it behaves

In SakuraOS settings, choose whether Terminal Assist stops these commands, only warns about them, or does nothing. The setting applies to both layers.
