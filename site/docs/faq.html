Frequently asked questions

The questions people ask before installing, and the ones they ask in the first week. Longer answers live on the pages linked from each one.

What is SakuraOS, exactly?

Arch Linux, with KDE Plasma, a kernel chosen by what your processor supports, and five applications built for it. It is not a fork of Arch and it does not hold packages back on a schedule: you are running Arch, with the decisions that usually take a weekend already made and a way back when an update goes wrong.

Is it just Arch with a theme?

No. The parts that are ours are the installer, the App Store, the Update Center, Terminal Assist, Sakura Settings, and the recovery environment that opens when a machine will not start. The theme is the least of it.

Do I need to know Arch to use it?

No. Nothing in normal use requires the terminal. If you do open one, Terminal Assist is there to stop the specific commands known to break an Arch install, and it can be switched off.

Will an update break my machine?

It can, the same as on any rolling release. Two things sit in the way. A restore point is taken before every package transaction, so going back is a reboot rather than a rescue. And every night the day's updates are installed on a machine of ours, restarted, and checked; anything that breaks it is held back from you with the reason attached. See Updates.

What happens if it will not boot?

After three failed starts the recovery environment opens by itself, lists your restore points in plain language, and puts the system back when you pick one. No live USB, no chroot. See Recovery.

Can I use the AUR?

Yes, and it is off until you turn it on, because it is build scripts written by other users that nobody reviews. Turning it on is one switch in Settings. What you install is then checked against every published AUR attack campaign from inside pacman, and you see the build script before it runs. See The AUR.

Can I use yay?

Yes. yay is the helper SakuraOS configures, and the campaign check is a pacman hook, so it runs whether the package came from the App Store or from yay in a terminal. The build script review is a store feature; yay shows its own diff instead.

Which kernel do I get?

The installer checks whether your processor supports x86-64-v3. If it does you get the tuned CachyOS build; if it does not you get the standard Arch kernel. Both are on the media and nothing else about the install changes. See Kernel.

Does it work offline?

Yes. The installation media carries everything a working desktop needs, including a browser, so an install with the cable out produces a complete system. Anything that has to be fetched, such as a different browser or the legacy NVIDIA driver, is skipped and named, and the installer tells you plainly that nothing will fetch it later on its own.

Is Secure Boot supported?

Yes, if your firmware is in setup mode when you install: the installer enrolls its own keys and signs both the system and the recovery images. If the firmware is not in setup mode the install completes normally with Secure Boot off, and says so.

How big is the download?

About 3.2 GB. One image, x86_64, no editions to choose between.

Can I dual boot with Windows?

Yes. The installer can take free space rather than the whole disk, and it does not touch the existing EFI partition beyond adding its own entry. Shrink the Windows partition from Windows first, and turn off Fast Startup, which leaves the filesystem in a state Linux will refuse to write to.

How do I get rid of it?

The same as any other Linux install: boot other media and remove the partitions. SakuraOS keeps nothing outside the disk you installed it on and writes no firmware settings beyond its own boot entry, which the firmware menu can delete.

Who is behind it?

A small project, in the open. Everything described in this wiki is in the repository, including the build pipeline that produces the image you downloaded.
