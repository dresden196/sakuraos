Troubleshooting

The problems people actually hit, roughly in the order they hit them. If the machine will not start at all, go to Recovery first: that is a solved problem here and does not need anything on this page.

Start here: what changed?

Almost every sudden fault on a rolling release follows something that changed. Before anything else, find out what: 

sakura-update history
# or, for everything pacman did
grep -E 'upgraded|installed' /var/log/pacman.log | tail -30

If the fault started after that list, you do not have to diagnose it. Take the restore point from before it and carry on with your day.

The machine boots to a black screen

Usually graphics. Restart, and when the boot menu appears choose SakuraOS Recovery, then a restore point from before the last update. If it happened on a brand new install rather than after an update, see Hardware for the NVIDIA notes: cards older than Pascal need the legacy driver, which is fetched rather than shipped.

It boots, but there is no desktop

You will land at a text login. Check whether the display manager is running: 

systemctl status sddm

If it failed, the reason is in journalctl -b -u sddm. If it is running and you still see no desktop, the graphics driver is the next suspect: journalctl -b -p err will usually name it.

No wireless

Check the radio is not switched off in software or by a hardware key: 

rfkill list
nmcli radio wifi on

If the adapter does not appear in ip link at all, it needs firmware the base install does not carry. dmesg | grep -i firmware names the file it wanted, and the package is almost always linux-firmware or a vendor package named after the chipset.

No sound

SakuraOS uses PipeWire. Most "no sound" is the wrong output selected rather than a broken stack: 

wpctl status          # what PipeWire can see
systemctl --user status pipewire wireplumber

If both are running and the device is listed, pick it in System Settings under Audio. If wpctl shows nothing at all, restart the user services with systemctl --user restart pipewire wireplumber.

pacman will not run

Two faults account for nearly all of these.

"unable to lock database"

Something died mid-transaction and left its lock. Make sure nothing is actually running first, then remove it: 

pgrep -x pacman || sudo rm /var/lib/pacman/db.lck

"invalid or corrupted package" or a signature error

Usually a truncated download or a stale keyring. Clear the cached copy and refresh the keys: 

sudo pacman -Sc
sudo pacman-key --refresh-keys
sudo pacman -Syu

If it names a SakuraOS package specifically, the mirror may have been mid-publish. Waiting a minute and retrying is the fix.

A command was refused

That is Terminal Assist, and it prints the reason and the exact override. If you want it out of the way permanently, Settings moves it between block, warn and off.

The disk is full

Two things grow: the package cache and old restore points. Neither is inside a snapshot, so clearing them does not affect what you can go back to. 

sudo pacman -Sc                 # cached packages
sudo journalctl --vacuum-size=200M
snapper -c root list            # then delete old ones from the Update Center

An update wants to remove something important

It will not be allowed to remove your last kernel or a package the system needs: the check inside pacman refuses, whatever asked. If you are certain, the refusal prints the override. If you are not certain, that refusal is the feature working.

A game will not start

See Gaming, which covers Proton versions, the Steam runtime and the launch options worth trying before anything else.

Still stuck

Collect the logs described in Logs and bug reports before asking. A report with the journal attached is usually answered; one without it usually turns into a conversation about how to get the journal.
