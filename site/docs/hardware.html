Hardware and drivers

Most of this is decided during the install without asking you. This page is what it decided, and what to do on the hardware where the answer is not automatic.

Graphics

The installer looks at what is in the machine and installs accordingly. On AMD and Intel that is the open driver in the kernel plus the userspace packages, and there is nothing to choose.

NVIDIA

Which driver you get depends on the age of the card, because NVIDIA dropped older ones from the current branch:

  • Turing and newer get the open kernel modules, which is what NVIDIA now recommends.
  • Maxwell and Pascal need the frozen 580xx branch. It is not on the media, because it is roughly 900 MB installed for a minority of machines, so it is fetched during the install. An offline install on one of these cards gets the open drivers and will want that package once it is online.
  • Older than Maxwell is Nouveau, and performance will reflect that.

The legacy branch is DKMS: it rebuilds against each new kernel, and one day it will stop building against a kernel nobody is going to fix it for. That is a property of the driver, not of SakuraOS, and it is the reason the card is worth replacing eventually.

Two cards

Laptops with Intel or AMD integrated graphics plus an NVIDIA card are detected as such, and the NVIDIA driver is installed alongside rather than instead. Which card a program uses is a per-program setting in Plasma.

Wireless and bluetooth

NetworkManager is installed and enabled, and bluetooth is enabled with it, so the Plasma pages for both work without setup. Adapters that need firmware from linux-firmware are covered, since that package is on the media. Anything needing a vendor firmware package will appear in dmesg asking for a file by name, which is usually enough to find the package.

Printers and scanners

CUPS is installed with its socket enabled rather than the service, so the printing stack costs nothing until something actually prints. Drivers for most printers come from the gutenprint and foomatic packages, which are already there, and scanners are handled by SANE with Skanpage as the front end. Adding a network printer is the Plasma page and nothing else.

Disks

The installer picks an I/O scheduler per drive rather than setting one globally: NVMe gets none, because the queue in the device is better than the one in the kernel, and rotational disks get one that assumes seeking is expensive. See Tuning.

Extra drives are not touched during installation. Mount them from the Plasma disk pages, or add them to /etc/fstab if you want them at boot.

Laptops

Power profiles are handled by power-profiles-daemon, which the Plasma battery applet drives. Updates only install on mains power by default, so a machine on battery will not run a transaction flat. Suspend and resume are the kernel's, with no SakuraOS-specific handling, which means a machine that suspends badly on Arch will suspend badly here.

Machines with 8 GB or less

Compressed swap in RAM is configured by default, which is why a machine with 8 GB stays usable under load rather than reaching for the disk. There is nothing to enable.

Firmware and Secure Boot

If your firmware is in setup mode during the install, SakuraOS enrolls its own keys and signs both the system and recovery images. If it is not, the install finishes with Secure Boot off and says so rather than failing. Both images are signed the same way, so recovery works with Secure Boot on, which is the reason snapshots are not separate boot menu entries. See Recovery.
