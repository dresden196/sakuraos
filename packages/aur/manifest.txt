# AUR packages rebuilt into sakura-core.
#
# A distro cannot build AUR packages during installation, so anything the
# installed system depends on has to be rebuilt and served from our own repo.
# These three are why sakura-core is a hard prerequisite for the installer
# rather than an optimisation: without them there is no snapshot boot menu,
# which is the entire rollback story.
#
# Format: <aur-package-name>
# Replaced by sakura-snapshot-boot (see packages/sakura-snapshot-boot).
# limine-snapper-sync
# limine-mkinitcpio-hook
# limine-entry-tool

# NVIDIA 590 dropped Pascal and Maxwell, and the only driver those cards have
# left lives in the AUR. A distro cannot build from the AUR during an install,
# so it is rebuilt here -- and once it is here, SakuraOS owns it, because
# upstream never will again. It is DKMS: it recompiles on every kernel bump
# and will eventually stop building against a kernel nobody will fix it for.
#
# List the PKGBASE, never an individual split package. nvidia-580xx-utils is
# one pkgbase that produces -utils, -dkms and opencl-nvidia-580xx together;
# asking for -dkms separately clones an empty AUR repo and fails with
# "PKGBUILD does not exist" even though the package was already built.
nvidia-580xx-utils

# Snap support. snapd is not in Arch's repositories, so a store backend for it
# would otherwise require the user to enable the AUR -- the very thing the
# store exists to gate. Rebuilt here so Snap works without that loop.
#
# This is a standing commitment: we maintain snapd on Arch, including the
# parts of its confinement that depend on AppArmor policies Arch does not
# carry, which makes Snap sandboxing here weaker than it is on Ubuntu.
snapd

# Build dependencies of zsync2, both AUR-only. They are listed ahead of it
# because the build installs each package as it is produced, so order here is
# the dependency order.
args
# cpr's check() fails one of thirty-two tests:
# GetRedirectTests.BasicAuthenticationRedirectSuccessTest asserts that the
# effective URL after a redirect still contains user:password@, which newer
# libcurl deliberately strips. The test is stale against Arch's curl rather
# than a defect in the library, so it is skipped here and only here.
cpr --nocheck

# AppImage delta updates. Arch's zsync is 0.6.6, which predates widespread
# HTTPS and cannot read a control file over it -- and every real AppImage
# update URL is https, so the packaged tool cannot update anything. zsync2 is
# the maintained rewrite that speaks it.
zsync2

# Browsers offered by the installer.
#
# The installer installs the chosen browser with pacstrap during the install,
# so the name has to resolve from a repository the target can reach. Three of
# the four originally offered did not: these are AUR-only, and the list even
# said "brave", which is not the AUR name either. Choosing the default browser
# would have failed the install, and nothing tested it.
#
# Vivaldi is deliberately absent: it is in Arch's extra, so rebuilding it here
# would shadow a perfectly good packaged copy for no reason.
#
# All -bin packages: these repackage an upstream binary rather than compiling
# a browser from source, which is the only reason carrying four of them is
# affordable.
zen-browser-bin
brave-bin
google-chrome
helium-browser-bin

# The two command-line AUR helpers, offered by Settings.
#
# Same reasoning as snapd above, and it matters more here. Installing yay from
# the AUR means building an unreviewed script, and the store refuses to do that
# without showing it to somebody first -- which is right, and is a strange
# thing to demand from a dropdown in a settings page. Rebuilt here, choosing a
# helper is an ordinary signed package install: no makepkg on the user's
# machine, no build toolchain pulled in, and it works with no network beyond
# our own repository.
#
# It is the same upstream PKGBUILD either way. The difference is who ran it:
# us once, on a build box, or every user separately on their own machine.
#
# A standing commitment, like snapd: both are AUR packages that move, and a
# stale helper in our repo is worse than no helper. yay is Go and paru is Rust,
# so each costs a compiler in the build container and a few minutes a build.
yay
paru
